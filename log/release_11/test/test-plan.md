Owner: Tester | 2026-10-31 Asia/Shanghai | Status: **REVISED — developer re-review pending; detailed design review pending**.

## Current observable behavior

`execute(config, output_dir, *, stop, after_row, adapter)` validates configuration, adapter, running-loop state and output collision before acquisition. The default coordinated adapter uses a one-tick delayed measurement, while the direct adapter observes the current boundary. The example prepares the coordinator and writes heater power once; each count cycle advances once, reads the prescribed columns and only commits a complete row. `RunResult` separately reports acquisition, persistence and plotting, stop, cleanup, final tick/time, data and model reset eligibility. `run()` returns verified reopened data or raises `RunFailure`; the CLI supports generate, stop and inspect with documented exit/output behavior. An example `StopRequest` and `RunResult` are separate from W03 bounded types, and persisted identity is `DataGroup.id`, not necessarily W03 `CountResult.run_id`.

The complete example currently owns an example-local scheduler and loop; W03 `run_count` owns its scheduler and loop. `execute` also owns the HDF5 writer, disposable read copy and plot resources. Setup, callbacks, storage and plot failures must remain distinguishable during migration. Existing v1 coordinated and v2 direct manifests, schema and legacy no-manifest behavior are characterized in `tests/test_thermal_adapters.py`, `test_thermal_manifest.py`, `test_thermal_metadata_contracts.py`, `test_thermal_example.py` and `test_thermal_execution.py`. W01 characterization in `test_m02_w01_characterization.py` and `test_huo_execution_contracts.py` includes private helper use; retain behavior assertions and explicitly record any fixture adaptation after design review rather than asserting private helper identity is public. W02 and W03 tests characterize the shared seam and synthetic client. These are existing assertions, not newly executed results.

## Review follow-up and concrete test design

**Approved setup decision (TP-W04-01):** Characterize failures in `_build_simulation`, `Coordinator.prepare`, and control write, as well as runner preflight failure before scheduler allocation. The old `execute` allocates its loop before setup and ordinarily reports `work_drained=True`, `loop_closed=True` after successful teardown; after model setup the retained coordinator may make `reset_after_run` eligible. The proposed design allocates no scheduler on these paths: the [Product decision](../reviews/setup-failure-product-decision.md) approves truthful false flags, no fake cleanup and reset ineligibility before allocation. After allocation, separately test observed drain/closure and reset eligibility under the documented conditions. In all cases assert original exception identity, terminal state, completed rows, stage, output/persistence absence, independent writer cleanup where applicable, and borrowed/global resources unchanged. Differentiate setup failure before coordinator creation from prepare/write failure after coordinator creation.

**Mapping (TP-W04-02):** Capture the `RunResult` passed to every callback: exact object/stop identity, completed rows and tick/time at each callback; assert callback-time stage `setup`, acquisition `not_started`, and terminal/drain/closure flags false; check finite validation before callback, requests made through the same stop object and no extra acquisition. Exercise runner preflight exceptions that provide no `CountResult`; assert cause identity and only observed evidence, with no assumed attachment. Inject runner interruption with a `count_result` and immutable interruption without attachment, assert the exact original reraised, available evidence mapped before independent example-owned cleanup, unavailable evidence not fabricated, and fallback diagnostics observable. Test simultaneous primary and writer-cleanup failures at an applicable writer-owning path and retain both without masking or asserting an impossible acquisition/writer overlap.

**Private fixture disposition (TP-W04-03):** `test_huo_execution_contracts.py` uses `_make_scheduler` for legacy Process behavior; move that executor into test-owned historical support or equivalent. `test_m02_w01_characterization.py` uses `_CountScheduler`/`_make_scheduler` for historical scheduler probes, count/scan and cleanup injection; preserve probes in test support and migrate actual example-path fault injection to the shared boundary. `test_thermal_example.py` uses `_make_scheduler` to assert preflight, teardown ordering and serial action behavior and `_acquire` for fault injection; migrate runtime injection to shared scheduler/runner seams while retaining public assertions, and move standalone historical action checks to test-owned support. `test_thermal_execution.py` patches `_make_scheduler` and `_acquire` for lifecycle/interruption evidence; exercise equivalent shared-boundary faults without losing result, cleanup or stop assertions. `test_thermal_metadata_contracts.py` calls `_acquire` directly for metadata; update fixture to invoke migrated path while preserving metadata checks. Maintain a per-test mapping in final test evidence; retain unchanged tests where possible.

**Fresh environment (TP-W04-04):** Create a new temporary virtual environment using `python -m venv <temporary-path>` without `--system-site-packages`; record `pyvenv.cfg` showing `include-system-site-packages = false` and `sys.prefix`/`sys.base_prefix`. Install the current checkout with `<venv>/bin/python -m pip install -e .` using declared dependencies and record actual installation command and outcome. Run guide commands with `MPLBACKEND=Agg` and unique temporary output directories, inspect each from a fresh interpreter, verify outputs/numerical values and repeat. Do not silently use the existing `.venv` or cached environment as the fresh environment. Package-index/network or dependency installation failure blocks this gate and is reported with evidence.
