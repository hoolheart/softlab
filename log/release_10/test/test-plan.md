# M02-W03 test plan and compatibility characterization

Owner: Tester | 2026-10-30 | Status: revised in response to developer review; re-review requested. The detailed design has Architect approval.

## Existing contracts and boundaries

The W02 `run_count` accepts a `Counter`, owns a new `SerialScheduler` and loop, rejects pending processes, a running event loop and nonempty records before acquisition, and invokes `process.reset()` before the first cycle. Ordinary operational errors are returned as `CountResult.cause`; interruptions are reraised with a result attached where possible. Stop is checked at cycle boundaries, after the completion check. Cleanup records scheduler stop, drain and loop closure separately. `CountResult` currently has no run UUID. A prior observed boundary may be stale when later inspection fails; tests must not interpret it as a current boundary. Reader failures before result creation are preflight exceptions.

Legacy `run_process` explicitly resets before execution. `SimpleProcess.reset` while running requests abort without preemption; idle reset clears finished status. Legacy `count` reset appends to its existing record rather than clearing it. These are independently characterized in `tests/test_huo_execution_contracts.py`. W02 tests cover serial dispatch, timeout distinctions, paired reads, stop timing, acquisition partial failures, primary/cleanup coexistence, interruptions, and borrowed-loop isolation. W03 retains those tests and executes the full regression suite, including scan and simulation clients. W03 must not silently redefine legacy reset or generic scheduler defects F-01/F-02.

## Test cases and evidence

Use synthetic `count` fixtures with event traces, a temporary in-memory record, injected exception objects, and no physical I/O. Assert identity, ordering, row content and actual flags; avoid merely matching implementation internals. Use the approved lifecycle design for public names, validity/freshness representation, UUID location, reset eligibility and exception precedence.

| --- | --- | --- |
| Preflight and ownership | Invalid process, total, readers, pending process, active event loop, nonempty record, and unsupported borrowed scheduler/loop input if exposed: reject before execution side effects; existing external loop and global scheduler remain usable. Preflight reader exception retains identity. | 01, 05, 09 |
| Setup and execution faults | Inject scheduler creation, start (false and exception), dispatch/commit and join failures, and acquisition advance/read faults. | Cleanup | Independently inject stop, task drain, loop close and runner close faults, including combinations; later cleanup is attempted; drain/close flags reflect observed outcomes; successful acquisition with any cleanup failure is not overall success. Use controllable synthetic tasks and safely release test-owned resources after fault injection. | 02, 05 |
| Interruption and stop | Interrupt before and after a row, during independent inspection and cleanup; assert an ordinary primary remains the cause when a later interruption is reraised, and the first of multiple interruptions is reraised after cleanup. Verify pre-requested, after-row and late stop, distinct request/acknowledgment, and no further cycle after acknowledgment. | 02, 03, 04 |
| Reset and repeat | Cover each documented reset eligibility state, ineligible reset and injected reset failure, preserving first terminal evidence and proving no hidden acquisition retry. Verify a bounded reuse claim is checked before the row reader; an initial preflight reader failure does not consume the claim, while a reset failure does. Legacy-used Counter freshness cannot be detected, and remains caller responsibility rather than a tested detection guarantee. Two fresh processes, records, models and owned execution resources have distinct run UUIDs; deterministic events and numeric rows match excluding time/UUID; first evidence unchanged. | 01, 06, 07, 08 |
| Compatibility | Run W01 execution characterization, W02 bounded tests, synthetic signal client and full unittest discovery; existing import paths and legacy Process/count/scan behavior remain intact. | 09, 10 |

A failure must remain open until independently rerun and closed by the tester; distinguish pre-existing failures and warnings from regressions. Execute `python -m unittest discover -s tests -p 'test_*.py'`, `python -m compileall -q softlab`, and `python -c "import softlab; print(softlab.__version__)"`, recording interpreter, counts, skips, warnings and limits. CI matrix verifies Python 3.9 and 3.13 only when actual candidate jobs pass. No new dependencies, hardware, persistence or W04 thermal CLI migration are required.

Constructor-failure injection distinguishes failure before a scheduler is returned from failure after allocating a loop: no inaccessible scheduler cleanup is assumed. The latter requires a deliberate injection seam in constructor setup and verifies that the constructor releases its owned allocation before raising.
