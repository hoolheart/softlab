# TU-006 test-case gate

Owner: sw-mike. Status: expected RED; developer review and detailed design
approval pending. Production unchanged. Proposed API below is a test contract
for review, not an assertion that implementation exists.

## Grounding: current VISA reality (unchanged production code)

Inspection of `softlab/tu/station/visa.py` at branch tip `401cff6` grounds
this contract (with the TU-001 matrix in `log/release_1/compatibility.md`):

- Construction is eager: `ResourceManager` creation, `open_resource`, a
  `MessageBasedResource` type check, `clear()` (when `device_clear=True`) and
  the timeout/termination assignments all run inside `__init__`. Any failure
  after acquisition (e.g. `clear()` raising) propagates **without closing the
  already-open resource** — OBS-003's failed-init cleanup gap, landed here
  per the PRD. Resource-manager ownership is likewise unspecified.
- `timeout` forwards raw numerics to the PyVISA resource while docstrings
  say seconds; PyVISA's convention is milliseconds. OBS-001 requires TU-006
  to document compatible units/defaults **without silently rescaling existing
  callers** — the raw-forwarding legacy path is characterized and guarded.
- Transport errors already propagate as identical exception objects (TU-001
  row "eager open/clear and transport errors"); this gate pins that as the
  error-cause policy for every new path too.
- There is no concurrency guard, no interruption/abort concept, and no
  operation-state reporting: PRD requires blocking, a concurrency guard, and
  abort-request vs confirmed-physical-stop separation.
- `@sim` (pyvisa-sim 0.7.1) has **no response-delay support** (verified: a
  `delay:` key is ignored and the dialogue is not matched), so blocking
  duration is timed with mocks; `@sim` verifies real resource outcomes
  (round trips, real millisecond timeout values, session open/close state,
  `*OPC?`-confirmed stop).
- `VisaHandle` is not a `Device`; adopting the approved TU-004 lifecycle
  contract (`supports`/`prepare`/`initialized`/`cleanup` semantics from
  `log/release_1/design/TU-004.md`) means mirroring its behavior outcomes
  compatibly, not inheriting it.

## Proposed minimal surface

Additive/behavioral, keeping legacy construction and usage compatible
(eager open+clear stays; `timeout` raw forwarding stays; `close()` stays):

- **Lifecycle adoption (group A, closes OBS-003):**
  - `VisaHandle.supports(capability) -> bool` — `'connection'`/`'prepare'`/
    `'cleanup'` are `True`; unknown names (including `''`) are `False`;
    detection never performs I/O and never raises.
  - `VisaHandle.initialized -> bool` — `True` after the unchanged eager
    successful open; `False` after `cleanup()`.
  - `VisaHandle.cleanup() -> None` — idempotent; releases the **owned**
    resource exactly once; a borrowed resource is never closed.
  - `VisaHandle.prepare() -> None` — no-op while initialized; after
    `cleanup()` re-opens the resource (repeatable cycle).
  - Failed-init cleanup: any post-acquisition failure in `__init__`
    (`clear()` or timeout/termination assignment) closes the acquired
    resource exactly once before the original exception object propagates.
  - Ownership: `VisaHandle.borrow(resource)` adopts an externally owned,
    already-open `MessageBasedResource` — no I/O, no reconfiguration; a
    non-owner release never closes it. Default address-based construction
    owns its resource.
- **Timeout units/defaults (group B, resolves OBS-001 additively):**
  - `VisaHandle.timeout_seconds` property (get/set) with documented seconds
    ↔ PyVISA-milliseconds conversion (×1000, both directions); `None`
    disables. Default 5.0 s (resource value 5000 ms), applied at
    construction, also via a `timeout_seconds` constructor keyword. Legacy
    `timeout` raw forwarding untouched.
  - Timeout expiry surfaces the original `VisaIOError` object unchanged.
- **Blocking/concurrency/interruption (group C):**
  - Operations block until completion or timeout.
  - An internal guard serializes concurrent operations (no interleaved
    resource calls), without changing single-threaded signatures.
  - `abort() -> report` requests interruption of the in-flight operation;
    the aborted call terminates promptly and propagates its underlying
    error object unchanged. The report separates software abort from
    confirmed physical stop: `report.aborted` is `True` while
    `report.stopped` and the handle's `stopped` flag stay `False`; an abort
    request performs no device writes claiming a stop. Abort with nothing
    in flight is a quiet no-op. **An abort request must never claim the
    equipment stopped.**
  - `confirm_stop() -> bool` is the only path that may report a physical
    stop: exactly one `'*OPC?'` query, `True` only on device-confirmed
    completion; transport errors propagate unchanged.
- **Error causes (group D):** identical-object propagation (pinned legacy
  policy); operations on a cleaned-up handle raise `RuntimeError` matching
  `'Invalid visa resource'` with zero resource I/O; `prepare()` recovers.

Designer may refine naming (`borrow`, `timeout_seconds`, report type,
`confirm_stop`) through an explicit test-plan revision; the acceptance
semantics above are the contract under test. Case groups are independent so
implementation steps (A: lifecycle/ownership; B: timeouts; C:
blocking/concurrency/interruption; D: error causes) can be validated
incrementally; coverage is not weakened by the grouping.

## Acceptance cases (`tests/test_tu_visa_contracts.py`, 16 cases)

Group A — lifecycle adoption and ownership:

1. `test_legacy_eager_open_and_close_unchanged` — **guard (green)**:
   eager open with `@sim` lib selection, `open_resource`, exactly one
   `clear()`, raw default timeout 5.0, `address`, explicit `close()` once.
2. `test_capability_detection_and_readiness_without_io` — `supports`
   vocabulary, case-sensitive unknown/empty names `False`, `initialized`
   `True` after eager open, and zero resource calls for detection.
3. `test_cleanup_idempotent_and_prepare_reopens` — `prepare()` no-op while
   initialized (no re-open/extra clear); `cleanup()` closes once;
   double-`cleanup()` no-op; `prepare()` re-opens (repeatable cycle).
4. `test_failed_initialization_closes_resource_before_propagating` —
   OBS-003: `clear()` raising in `__init__` closes the resource exactly once
   and propagates the identical `VisaIOError`; a failing `timeout`
   assignment cleans up identically.
5. `test_borrowed_resource_is_never_closed_by_non_owner` —
   `VisaHandle.borrow(resource)`: no clear/config writes at adoption;
   `cleanup()` (twice) never closes; the owner keeps full use.

Group B — timeout units and defaults:

6. `test_legacy_timeout_raw_forwarding_unchanged` — **guard (green)**:
   constructor/set/get raw forwarding preserved (TU-001 OBS-001 legacy).
7. `test_timeout_seconds_converts_to_visa_milliseconds` — `timeout_seconds`
   2.5 → resource 2500; owner-side 4000 → 4.0; `None` disables both ways;
   legacy raw path undisturbed.
8. `test_timeout_seconds_default_and_constructor_keyword` — default 5.0 s →
   resource 5000 ms; `timeout_seconds=1.5` constructor keyword → 1500 ms.
9. `test_timeout_error_propagates_original_cause` — mocked read raising
   `VisaIOError(VI_ERROR_TMO)` propagates as the identical object;
   `@sim` round trip unaffected by the explicit timeout (5.0 s on a real
   resource).

Group C — blocking, concurrency, interruption:

10. `test_operations_block_until_completion` — **guard (green)**: mocked
    read sleeping 0.15 s; the call blocks at least that long and returns
    the completed value exactly once (`@sim` cannot delay, see Grounding).
11. `test_concurrent_operations_are_serialized` — two barrier-started
    threads; resource call events must be `[start, end, start, end]` —
    strict serialization (currently interleaves: `[start, start, end, end]`).
12. `test_abort_requests_interruption_without_claiming_stop` — blocked
    read interrupted: identical `VisaIOError(VI_ERROR_ABORT)` object
    propagates; `report.aborted` `True` but `report.stopped`,
    `handle.stopped` `False`; **no write commanding a stop**; idle abort is
    a quiet no-op.
13. `test_confirmed_stop_requires_device_confirmation` —
    `confirm_stop()` performs exactly one `'*OPC?'` query; `'0'` → `False`
    and `stopped` stays `False`; `'1'` → `True` and `stopped` becomes
    `True`; transport error propagates as the identical object.

Group D — error causes and `@sim` outcomes:

14. `test_transport_errors_propagate_as_identical_objects` —
    **guard (green)**: query error identity and exactly-one-call.
15. `test_cleaned_up_handle_rejects_operations_without_io` — all five
    operations raise `RuntimeError` matching `'Invalid visa resource'`
    with zero resource calls after `cleanup()`; `prepare()` recovers.
16. `test_sim_end_to_end_resource_outcomes` — real `@sim`: borrowed
    resource adopted as-is, queried, `confirm_stop()` against the
    simulator's real `*OPC?` → `"1"`, non-owner cleanup leaves the real
    session open (owner still queries; `session is not None`); owned handle
    reads 5.0 s from the real 5000 ms resource, queries Keithley sim,
    post-cleanup operations raise without I/O, `prepare()` re-opens.

Guards (cases 1, 6, 10, 14) pass against unchanged code; the other 12
require the new contract and are the RED cases. Incremental validation:
group A cases 2–5, group B cases 7–9, group C cases 11–13, group D cases
15–16 can each go green per implementation step.

## Actual red evidence

On Python 3.13.15 (`.venv`) with writable `MPLCONFIGDIR=/tmp/softlab-mpl`
and `XDG_CACHE_HOME=/tmp/softlab-cache`, from repository root on branch
`codex/tu-006-visa-contracts` (tip `401cff6` plus the test commit below,
production unchanged):

- `.venv/bin/python -m unittest discover -s tests -p 'test_tu_visa_contracts.py' -v`:
  **4 pass, 12 fail (10 errors + 2 failures)** of 16. Every error is
  `AttributeError` for the missing contract API (`supports`, `prepare`,
  `cleanup`, `borrow`, `timeout_seconds`, `abort`, `confirm_stop`); the two
  failures are the two behavioral gaps this task exists to close —
  failed-init cleanup (`close` called 0 times, OBS-003) and the missing
  concurrency guard (events `['start', 'start', 'end', 'end']`).
  The 4 passing cases are the intended guards (1, 6, 10, 14).
- Same command with `-W error::SyntaxWarning`: identical 4/12 result, no
  warning escalated — zero warnings.
- `.venv/bin/python -m compileall -q softlab`: clean.
- Import smoke: `import softlab` (0.3.0) and `from softlab.tu.station import
  VisaHandle` succeed.

Existing suites on the same run (all from repository root, same
environment), all green with **zero skips and zero warning escalations**:

- `test_tu_lifecycle.py`: **10 PASS** (includes the TU-004 test-phase
  recovery-cycle case).
- `test_tu_operations.py`: **7 PASS**.
- `test_tu_descriptions.py`: **11 PASS**.
- `test_tu_contracts.py`: **17 PASS** (TU-001 characterization, including
  VISA eager-open/timeout/non-message rows).
- `test_tu_measurements.py`: **10 PASS**.
- `test_compatibility.py`: **5 PASS** (includes the `@sim` simulator case;
  pyvisa-sim 0.7.1 present, so no skip).

New acceptance tests intentionally block full-suite green until
implementation; no CI/testing completion is claimed at this gate. All
resources are mocks or the `@sim` simulator (pyvisa-sim 0.7.1, simulated
devices only); no real hardware accessed, no new runtime dependencies, no
unjustified skips. OBS-001 (unit discrepancy) is resolved additively
(`timeout_seconds`) while the legacy raw path is guarded unchanged; OBS-003
is pinned by cases 4 and 16; the pre-existing baseline defects recorded in
earlier gates remain unchanged production code.
