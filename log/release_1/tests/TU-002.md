## Proposed minimal surface

`Parameter.describe(metadata=None)`, `Device.describe(metadata=None)` and
`Station.describe(metadata=None)` return independent JSON dictionaries.
`schema_version` is integer 1; names remain names, `type` uses qualified class
name text, and parameter permissions are explicit. Device dictionaries retain
`parameters` and `children`, stations retain `devices`. Nesting uses existing
lookup keys (including after an object's name changes), so paths can be derived
without inventing immutable/global IDs or adding a path cache.

Metadata is opt-in per invocation: string-key dictionaries, lists, JSON scalars
and finite numbers. Unknown string keys survive. Unsupported objects/non-string
keys/nonfinite floats raise TypeError or ValueError; no arbitrary string coercion.
Returned metadata is detached from input. No constructor changes are required.
Designer may refine this surface through an explicit test-plan revision.

## Acceptance cases (`tests/test_tu_descriptions.py`)

1. Versioned JSON parameter description and read/write permissions; no value.
2. No read hook or legacy snapshot override invoked by description.
3. Arbitrary runtime object remains opaque; legacy snapshot and value unchanged.
4. Nested device/parameter identity via lookup keys survives parameter rename.
5. Recursive station description is JSON; legacy snapshot unchanged.
6. VISA command description performs zero I/O; subsequent legacy call still writes.
7. Unknown JSON metadata keys preserved, deep-copy isolation.
8. Unsupported metadata rejects explicitly without coercion.
