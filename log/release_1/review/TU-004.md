## Design compliance

- **`supports()`** (device.py:186-213) is the exact design pseudocode:
  `return capability in ('prepare', 'cleanup')`. Probed directly:
  `True` for `'prepare'`/`'cleanup'`; `False` for `'connection'`, unknown
  names, `''`, and `'PREPARE'` (ordinary case-sensitive equality as
  pinned). Pure membership test — no I/O, no resource manager, never
  raises. The docstring states the base vocabulary, the never-raises
  guarantee, and the subclass extension rule with the recommended
  additive form and the out-of-contract warning for dropping
  `'prepare'`/`'cleanup'`.
- **`prepare()`** (device.py:215-256) matches the algorithm exactly:
  the `if self._initialized: return` is the **single** early return;
  `_needs_cleanup = True` is armed **before** `self._prepare_impl()`;
  `_initialized = True` is set only after the hook returns. Source
  inspection confirms **no `try`/`except`, no `raise`, no
  `_needs_cleanup` guard** anywhere in the body — exception identity
  (case 6) is structurally trivial, and decision 5 is honored as
  documentation-only pinning. The mandated verbatim contract text
  ("After a failed ``prepare()`` (the hook raised), the device holds a
  pending partial acquisition: ``cleanup()`` MUST be called before
  calling ``prepare()`` again. Re-preparation without an intervening
  ``cleanup()`` is outside the lifecycle contract and its behavior is
  not guaranteed.") is present verbatim (whitespace-normalized line
  wraps only).
- **`initialized`** (device.py:258-275) is a read-only `@property`
  returning `_initialized`; the docstring pins the exact readiness
  transitions (fresh `False`; `False → True` only on successful
  `prepare()`; `True → False` on `cleanup()`; stays `False` through a
  failed `prepare()`).
- **`cleanup()`** (device.py:277-313) matches the algorithm exactly:
  non-owner early return on `not self._needs_cleanup`; both
  `_needs_cleanup = False` and `_initialized = False` are cleared
  **before** `self._cleanup_impl()` — discharge-before-hook, so the
  release runs exactly once even if the hook raises and is never
  implicitly retried. Probed directly with a raising `_cleanup_impl`:
  the original exception propagated, the hook ran exactly once across
  two `cleanup()` calls, and the device ended not initialized.
- **Invariant.** `_initialized ⇒ _needs_cleanup` was probed across the
  full transition cycle (fresh → prepare → double-prepare → cleanup →
  cleanup): states were `(False,False) → (True,True) → (True,True) →
  (False,False) → (False,False)`; the forbidden `(True,False)` state is
  unreachable by construction since `_initialized` is only set after
  arming and only cleared together with `_needs_cleanup`.
- **Docstrings.** Class docstring gained the four public members in the
  `Public properties:`/`Public methods:` lists plus both mandated notes:
  (a) the single-threaded contract (decision 3), and (b) the OBS-006
  precedence note with explicit `parameter(key)`/`child(key)` lookup
  remaining available (decision 4). Method docstrings carry
  Args/Returns/Errors/Side-effects sections in the surrounding repo
  style (sections omitted only where inapplicable — `supports` never
  raises, so it has no `Errors:` section; the never-raises guarantee is
  stated in prose as the design requires). Both hook docstrings state
  the base no-op, the owned-resources-only rule, the at-most-once
  guarantee, and "subclasses must not override `prepare()`/`cleanup()`
  itself".
- **Additive-only.** The diff is pure insertion: constructor signature
  unchanged (only the two field assignments `_initialized = False`,
  `_needs_cleanup = False` appended); no import added or changed; no
  `__init__.py` change; VISA untouched (OBS-003 remains deferred to
  TU-006); no new dependency — not even a `typing` addition.
- **Delegation precedence probed.** A parameter literally named
  `'cleanup'` (and separately `'prepare'`) is shadowed for
  attribute-style access by the real member, while
  `device.parameter('cleanup')` explicit lookup still returns the
  parameter — exactly the decision 4 disposition.
- **Style.** No line exceeds the 80-column Black width in `device.py`;
  no syntax beyond py39.
