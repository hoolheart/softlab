## Design compliance

- **`execute()`** (visa.py:312-344) matches the contract exactly: a single
  direct positional `self._handle.write(self._cmd)` followed by
  `return self._value`. No `try`/`except` anywhere in the path, no hook
  invocation (`before_get`, `get()`, `__call__` are not called), no encoder
  or decoder applied, no permission check. The docstring explicitly states
  the path is not gated by legacy `gettable`/`settable` permissions,
  discharging the arch review's non-blocking observation.
- **`describe_operation()`** (visa.py:346-377) returns a fresh four-field
  dict literal per call: `schema_version: 1` (int), `name` (`self._name`),
  `effect: 'write'`, `executions_per_call: 1` (int). It reads only stored
  scalars — zero I/O, no handle access, no command string or resource
  address in the result. JSON-compatible (round-trip asserted by case 2).
- **TU-002 separation.** `VisaCommand` does **not** override `describe()` —
  verified at runtime (`'describe' not in VisaCommand.__dict__`); the
  inherited TU-002 lookup is unchanged and does not leak `*RST`. The
  operation-description schema lives in its own namespace as designed.
- **Legacy compatibility.** Constructor, `before_get`, and `snapshot()`
  (including the legacy `cmd` field) are byte-identical to the base commit;
  the diff is confined to `visa.py` and is purely additive. No new imports —
  `Any`/`Dict` were already imported. No new third-party dependency.
- **Docstrings and style.** Both methods carry Args/Returns/Errors/
  Side-effects docstrings in the surrounding repo style with signature
  annotations; the class docstring gained the required two-line
  `Public Methods:` note. No line exceeds the 80-column Black width; no
  syntax beyond py39.

## Compatibility

Denied `set` still raises `RuntimeError` from `Parameter.set` before any
write (case 3/5); legacy `()`/`get()` each perform exactly one write via
`before_get` (case 3); `snapshot()` performs no I/O (case 3). I additionally
probed the arch review's latent corner — `VisaCommand(..., gettable=False)`:
legacy `get()` is denied with zero writes while `execute()` still performs
exactly one write, matching the design's categorical "always permitted"
rule. Note this construction emits a **pre-existing** `Parameter.__init__`
warning ("neither settable and gettable", parameter.py:183) that predates
TU-003 and is outside its scope; the shipped paths introduce no warnings.

## Review issues and closure

No issues found. Independent spot checks beyond the acceptance tests
confirmed: mutation independence of `describe_operation()` (mutating a
returned dict leaves the next call's result intact — the design decision-1
guarantee whose formal assertion remains owed to sw-mike in the test
phase); dict identity differs across calls; `describe()` is not overridden
on `VisaCommand`; two `execute()` calls write exactly twice; the stored
value is returned by identity (`is True`).
