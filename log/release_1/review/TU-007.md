## Design compliance

### Step A — identity/description (`42767e3`)

- **`describe()` schema_version 1** (model.py:92-117): keys
  `schema_version` (pinned `int` literal 1 — probed
  `type(...) is int`), `name` (`self.name`, `''` allowed), `model`
  (`type(self).__qualname__`), `attributes` mapping each key to
  `{'description': ...}` — exactly the design schema. Reads
  `_attr_descriptions[key]` by direct index (loud invariant surfacing,
  per the design edge-case note). Fresh dict per call — probed:
  repeated calls return distinct objects; mutating a result does not
  affect the model.
- **Zero evaluation** — probed with a `Fragile` model whose
  `calculate_features` records calls and raises: `describe()` succeeds
  with zero calls recorded (case 5 green).
- **`add_attribute` ordering invariant** (model.py:87-90): duplicate
  `ValueError` FIRST (legacy message shape
  `'Already has the attribute with key "{key}"'` preserved — probed
  verbatim), `LimitedAttribute(vals, initial_value)` construction
  (initial-value validation) SECOND, `_attr_descriptions[key] =
  description` LAST. Both rejection paths probed:
  - duplicate key with `description="orphan?"` → `ValueError`, both
    dicts unchanged, no orphan entry;
  - out-of-range initial value (`ValInt(0, 10)`, initial `99`) →
    validator `ValueError` from `LimitedAttribute.__init__`, key absent
    from **both** `_attributes` and `_attr_descriptions`.
- **Parallel dict invariant** `set(_attr_descriptions) ==
  set(_attributes)` — probed after every success and every failure
  path. Legacy three-argument calls byte-compatible (probed:
  `add_attribute("extra", ValInt(), 1)` works, description defaults to
  `''`).

### Step B — configuration surface (`6c0f227`)

- **Pinned import form** (model.py:3): plain `import collections.abc`;
  both use sites spell `collections.abc.Mapping` fully (the phase-1
  `isinstance` at model.py:176 and the `configure` annotation at
  model.py:149). `Tuple` added to the existing `typing` import
  (model.py:9). The module-level `Mapping` binding stays the theory
  class — probed three ways: `model_mod.Mapping is
  softlab.tu.theory.mapping.Mapping`; `TheoryModel.get_mapping.__
  annotations__['return']` is the theory `Mapping`; `Mapping((2,1),
  (2,1), lambda x: x)` instantiates and is callable (the `Motion1D`
  example's call shape). Guard 3 (public import identity) green.
- **`supported_configuration()`** (model.py:119-129):
  `tuple(self._attributes.keys())` verbatim — probed `type(...) is
  tuple`, `== ("value", "gain")` in registration order, unchanged after
  a value write (value-independent declaration, case 6).
- **`configuration()`** (model.py:131-146): fresh dict via
  `attr.get()` per call — probed: distinct objects per call, mutation
  of a result does not affect the model.
- **`configure()` three-phase** (model.py:148-186): exact design
  pseudocode — (1) non-`collections.abc.Mapping` → `TypeError` naming
  the received type (probed for `str`, `None` → "NoneType", `list`);
  (2) unknown key → `KeyError(key)` naming the key (probed:
  `"nope"` in `str(exc)`); (3) pre-validate ALL via
  `self._attributes[key]._vals.validate(value)` — the acknowledged
  `_vals` private access is present exactly as the design's recorded
  tradeoff — then apply ALL via `set()`. **Zero partial application
  probed in both orders**: `{"value": 5, "gain": -1.0}` and
  `{"gain": -1.0, "value": 5}` both raise `ValueError` (ValNumber(0.0)
  rejects negative) with the full previous configuration
  `{"value": 2, "gain": 1.5}` intact — the multi-key guarantee the
  suite pins only for single keys. Empty mapping is a no-op returning
  `None` (probed). `MappingProxyType` accepted — the
  `collections.abc.Mapping` check does not over-restrict to `dict`
  (probed). Round-trip identity probed: configure → read → re-apply →
  unchanged, delegated access agrees (single source of truth).
- **JSON-safety-as-author-responsibility docstring** present verbatim
  in `configuration()` (model.py:133-140, decision 3).

### Step C — strict evaluation (`af72612`)

- **`evaluate_features`** (model.py:188-218) calls
  `calculate_features()` **directly at both call sites** — neither path
  routes through the `features` property (verified by source
  inspection; the property name does not occur in the method body).
- **Strict path** (model.py:213-214): bare `return
  self.calculate_features()` — no `try`, no `raise ... from`. Probed:
  the raised object `is` the injected `ValueError("bad")` instance
  (assertIs identity, cases 10–11 green).
- **Lenient path** (model.py:215-218): `except Exception: return {}` —
  OBS-005 semantics for every `Exception` (probed: `{}` for both
  `evaluate_features()` and `evaluate_features(strict=False)`).
- **BaseException divergence is real** — probed with an injected
  `KeyboardInterrupt` instance: it propagates identically (`is` the
  injected object) on **both** the strict and lenient new paths, while
  the legacy `features` property still swallows it and returns `{}`.
  The divergence is intentional per the corrected design (OBS-005 does
  not certify the process-control swallow; new code must not extend
  it).
- **`features` property byte-identical** to pre-task state: the full
  task diff contains exactly one deletion (the old `add_attribute`
  signature line); the property body (model.py:58-64) is untouched
  context. Confirmed by diff inspection and by guard 1 + the
  KeyboardInterrupt probe.
- **Reserved-name shadowing** (decision 1) probed: a model registering
  an attribute under the reserved key `"configure"` sees dotted access
  resolve to the method, and the OBS-006 escape hatch
  `model._attributes["configure"]()` reaches the delegated attribute.
