## Design compliance

### Step A — lifecycle/ownership (`a57b63b`)

- **State fields and invariant** (visa.py:120-133): `_resource`,
  `_manager`, `_initialized`, `_owns_resource`, `_stopped`, stored
  construction config (`_device_clear`, both terminations,
  `_timeout_raw`) — exactly the designed field set; no
  `FailedPendingRelease`/`_needs_cleanup` (grep confirms these exist
  only in `device.py`, TU-004's own). Invariant `_resource is not None
  ⇔ _initialized` holds by construction: `_acquire()` sets both
  together (visa.py:214-215), `cleanup()` discharges both together
  (visa.py:345-348).
- **`_acquire()` extraction** (visa.py:156-215) is the exact design
  pseudocode: `open_resource` outside the guard (a raise there means
  nothing was acquired — no close); the legacy non-message rejection
  path (close once + `TypeError`, unchanged message shape) sits
  **before** the `try`, so no double close; the `except` closes the
  acquired resource with exactly one attempt, a failing close is logged
  (`_logger.warning(..., exc_info=True)`) and suppressed, and the
  re-raise is a **bare `raise`** (visa.py:213) — identical exception
  object (OBS-003; case 4 `assertIs` green). The `except Exception as
  e: ... raise e` in `__init__` (visa.py:152-154) is pre-existing
  legacy code outside the TU-006 diff; in Python 3 it re-raises the
  same object, so identity is preserved (verified by case 4 and probe).
- **`supports()`** (visa.py:244-269): vocabulary
  `('connection', 'prepare', 'cleanup')`, case-sensitive, `''` and
  unknown names `False`, no I/O, never raises — probed:
  `[True, True, True, False, False, False]` for
  `('connection','prepare','cleanup','Connection','','x')`.
- **`prepare()`** (visa.py:271-313): no-op while initialized; borrowed
  handle raises `RuntimeError('Cannot re-open a borrowed visa
  resource')` (probed); re-open via the **retained** manager through
  `_acquire()`. Failed re-open probed: original exception identity
  (`e is err` → `True`), `initialized` stays `False`, `_resource` stays
  `None`, no extra close, and a later `prepare()` retries successfully
  — the repeatable cycle with no failed-pending state, per
  mirror-divergences 1–2.
- **`cleanup()`** (visa.py:315-350): discharges state **before** the
  release, resets `_stopped`, closes the owned resource exactly once;
  borrowed resource never closed (probed: `res.close.called == False`
  after `cleanup()` on a borrowed handle).
- **`close()` → `cleanup()`** (visa.py:504-527) with the mandated
  docstring text present verbatim (idempotence change, second `close()`
  now a no-op, ownership awareness, no production caller depended on
  double-close).
- **`borrow()`** (visa.py:352-400) matches the design pseudocode field
  for field, including `cls.__new__(cls)` bypass, `_address` from
  `resource_name` (informational), `_owns_resource = False`,
  `_device_clear = False`, `_timeout_seconds = 5.0`; type check mirrors
  the constructor policy; non-intrusive (no I/O — case 5 green).

### Step C — serialization/abort/confirm_stop (`002855e`)

- **`_serialized()`** (visa.py:554-590) is the exact design pseudocode:
  the `RuntimeError('Invalid visa resource')` check sits **inside**
  `_op_lock`, `_in_flight` incremented after the check and decremented
  in `finally`, and no `try/except` wraps the operation call — error
  identity preserved by construction. Post-cleanup rejection probed:
  zero resource calls.
- **Legacy call shapes preserved** (visa.py:529-552):
  `read(encoding=encoding)`, `read_raw(size=size)`,
  `write(message=message, encoding=encoding)`, `query(command, delay)`
  positional — byte-compatible with the legacy forms (guard 10 green).
- **`abort()`** (visa.py:592-626): lock-free, reads `_in_flight`
  without the lock, records no state, performs no I/O, returns
  `AbortReport(aborted, stopped=False)` — never claims a physical stop.
  Probed from a second thread while a `read()` blocked: report
  `(True, False)`, `handle.stopped` stays `False`, zero writes to the
  device; idle abort returns `(False, False)`. **No `_abort_requested`
  anywhere** (grep clean) — the rejected entity stayed rejected.
- **`stopped` latch** (visa.py:628-650): `False` initially, set only by
  a device-confirmed `confirm_stop()`, reset by `cleanup()` — all three
  probed.
- **`confirm_stop()`** (visa.py:652-683): delegates to
  `self.query('*OPC?', None)` (serialized, exactly one query per call —
  `r.query.assert_called_with('*OPC?', None)` probed), parses
  `str(response).strip() == '1'`. Probed: `'0'` → `False`, latch
  unchanged; `'1\r'` → `True`, latch set; subsequent `'0'` → `False`
  with the latch **persisting**; `cleanup()` resets. Conservative
  confirmation with no third outcome, as designed.

## Review issues and closure

### [Medium] Issue 1: `timeout_seconds` docstrings omit two mandated statements

- **Location**: `softlab/tu/station/visa.py:415-468` (`timeout_seconds`
  getter and setter docstrings).
- **Description**: The design's docstring requirements mandate that
  `timeout_seconds` "state seconds↔milliseconds ×1000 conversion in
  both directions, `None` disables both ways, **the 5.0 s default**,
  and that **the legacy raw `timeout` property is undisturbed**"
  (`log/release_1/design/TU-006.md`, "Docstring requirements"). The
  getter/setter docstrings cover the ×1000 conversion and the `None`
  handling in both directions, but state neither the 5.0 s construction
  default nor that the legacy raw `timeout` property is undisturbed.
  (The default appears only in the `__init__` docstring; the class
  docstring's OBS-001 note describes the resolution but does not state
  the undisturbed-posture guarantee for the legacy property.)
- **Impact**: Documentation completeness only — zero behavioral impact;
  the mandated `__init__` text already documents the 5000 ms default,
  so a reader is not misled. But the design mandate is explicit and
  per-member, and this review admits no undocumented deviation.
- **Recommendation**: Add one sentence to the `timeout_seconds` getter
  docstring (or split across getter/setter) stating that the
  construction default is 5.0 s (applied as 5000 ms when `timeout` is
  not given) and that the legacy raw `timeout` property is undisturbed
  by this property. Docstring-only change; no re-test impact beyond the
  standard suite re-run.
- **Status**: RESOLVED.

- **Resolution note** (re-review at `3314718`, docstring-diff scope):
  the fix adds one sentence to the `timeout_seconds` getter docstring
  (visa.py:421-423): "The construction default is 5.0 s (applied as
  5000 ms when the raw ``timeout`` is not given), and the legacy raw
  ``timeout`` property is undisturbed by this property." This covers
  **both** missing mandated statements — the 5.0 s default (with the
  5000 ms application detail) and the undisturbed legacy `timeout`
  posture — matching the design's per-member mandate
  (`log/release_1/design/TU-006.md`, "Docstring requirements"). The
  pre-existing getter/setter text already covers the ×1000 conversion
  and `None` handling in both directions, so the mandate is now
  complete. The commit `3314718` touches **only** that docstring
  (+4/−0 in `softlab/tu/station/visa.py`; no code, no behavior change).
  Re-verified: `python -W error -m unittest discover -s tests -p
  'test_*.py'` → 77 tests, OK, zero warnings/skips.
